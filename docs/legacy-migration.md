# 舊帳搬進 App：轉換程式使用說明

給翰陞在自己的 Mac 上照做。目的：把 2026-11-08 的唯讀備份匯出轉成一個 App 的帳本檔（SQLite），之後用 AirDrop 傳到 iPhone，走「匯入備份檔」匯入（票 16）。
舊系統（ASP.NET Core＋SQL Server）全程不被動到：這個工具只讀匯出的 JSON 檔，不連資料庫。

**私人資料不進 Git。** 匯出目錄與輸出檔都放在 repo 的 `.private/` 之下（已被 Git 忽略）；工具也會拒絕寫到其他位置。

## 搬什麼、不搬什麼

| 搬入 | 不搬 |
|---|---|
| 全部交易（含合法重複的列，不去重）、分類、帳戶、成員 | 員工帳號、密碼、權限 |
| 財務文件：58 個月月結、上限版本、調整、核對紀錄——**原樣帶入，不重算**，17 個月的歷史總資產差異保留 | 原始 CSV、年度財報等外部檔案 |
| 信用卡明細；投資標的、期初投入宣告、交易、市值快照（保留來源編號與小數） | — |
| 各帳戶的開帳日與開帳餘額（見下） | — |

## 前置條件與準備（照順序做一次）

1. **找到匯出（在 Windows）。** 匯出在 `C:\Users\User\Documents\記帳\cloudflare-finance\.private\` 底下（`docs/cloudflare/baseline.md` 記載：私人資料在 `.private\ERPDB_CloudflareBaseline_20261108_115129\`）。要用的是其中含有 `manifest.json` 與一堆 `dbo.*.json` 的那個資料夾（下稱「匯出資料夾」）。**不要修改裡面任何檔案**；工具會逐檔核對 SHA-256，並確認它就是 baseline.md 記錄的那一份（資料庫名稱 `ERPDB_CloudflareBaseline_20261108_115129`、16 張表共 7,823 列、交易 7,033 筆（涵蓋 2017-06-04 至 2026-11-06）、58 個月結、歷史資產差異 0）。任何一項不符都會拒絕。
2. **搬到 Mac，位元組不變。** 在 Windows 把整個匯出資料夾壓成一個 zip（右鍵 → 傳送到 → 壓縮的資料夾），用 AirDrop、隨身碟或你信任的私人傳輸方式傳到 Mac。不要經過會改檔案內容的工具（例如會轉換換行或編碼的編輯器、雲端同步的「文字預覽」）。
3. **在 Mac 安裝 Node 24**（從 nodejs.org 下載 24 版安裝；終端機輸入 `node --version` 要顯示 v24 開頭）。不需要 `npm install`：工具只用 Node 內建功能。
4. **在 Mac 取得程式。** 打開「終端機」：

   ```bash
   git clone https://github.com/THB-TW/ERPAPP.git ERPAPP
   cd ERPAPP
   git checkout claude/project-thread-xdtlp5   # 合併之後改用預設分支，不需要這行
   ```

5. **解壓匯出到 repo 的 `.private/` 底下**（這個資料夾已被 Git 忽略，工具也只接受這個位置）：

   ```bash
   mkdir -p .private/app-ledger
   unzip ~/Downloads/<匯出資料夾>.zip -d .private/
   ls .private/<匯出資料夾>/manifest.json    # 要看得到這個檔案
   ```

   （也可以用 Finder 雙擊解壓後拖進 `.private/`；重點是匯出資料夾直接放在 `.private/` 之下。）

> 關於清冊雜湊：`baseline.md` 只記了原生備份檔的 SHA-256，沒有記這份匯出的清冊（`manifest.json`）雜湊。所以工具靠「baseline.md 記錄的身分」（上面第 1 點）加上逐檔 SHA-256 來確認輸入。**第一次成功後，請把摘要印出的「來源清冊 SHA-256」回報，之後會補記進 baseline.md**；補記之後，可以用 `--manifest-sha256` 再多釘一層。

## 執行

在 repo 根目錄之下：

```bash
cd apps/mobile
npm run legacy-convert -- \
  ../../.private/<匯出資料夾> \
  ../../.private/app-ledger/ledger.sqlite
```

- 輸出檔必須在 `.private/` 之下、而且**事先不存在**；已存在就拒絕，不覆寫。要重跑請換檔名（或你自己確認後刪掉舊檔）。輸出檔權限是只有你自己能讀寫（600）。
- 這個指令已關掉兩種固定警告（`MODULE_TYPELESS_PACKAGE_JSON`、SQLite 的 `ExperimentalWarning`）。如果你改用 `node tools/legacy-convert/cli.ts ...` 直接執行，會看到這兩種警告，它們不影響結果。
- 工具先寫到 `ledger.sqlite.partial`，寫完會**關檔後重新打開**，把交易、帳戶、分類、成員、開帳日、財務文件全部讀回來與要寫入的內容逐筆比對，通過才改成正式檔名；失敗時不會留下任何輸出。若上次被中斷，會留下 `ledger.sqlite.partial`，下次執行會明講是哪個檔，確認後把它刪掉再跑。
- 詢問需要在互動的終端機回答。如果輸入不是終端機（例如用管線餵資料）或中途按 Ctrl-D 關掉輸入，工具會停下並說明，改用下面的 `--account`／`--opening` 事先指定即可。

### 可選參數

| 參數 | 用途 |
|---|---|
| `--manifest-sha256 <雜湊>` | 選填。匯出清冊（`manifest.json`）的 SHA-256 必須相同，否則拒絕。 |
| `--mixed-flow split` | 同一個分類名稱同時有收入與支出時，把**收入**那一邊拆成「原名（收入）」另一個分類（見「停下來的情況」）。 |
| `--account 名稱=種類` | 事先指定帳戶種類：`cash`、`bank`、`credit_card`、`e_wallet`。可重複。 |
| `--opening 名稱=金額` | 事先指定該帳戶在搬遷截止月月底的餘額（整數，可含逗號；信用卡填未繳金額的**負數**）。可重複，優先於自動回推。 |
| `--card-account 名稱` | 舊信用卡明細沒有卡識別；多卡時指定全部明細所屬的卡，不自動分卡。 |
| `--investment-account 編號=名稱` | 為開帳日後的帳內投資買賣，明確指定來源交易編號與帳戶完整名稱。可重複，例如 `--investment-account '15=銀行'`（虛構編號）。未知編號、未知帳戶或歷史交易的對應會拒絕。 |
| `--no-prompt` | 不詢問；需要回答的地方改為停下並列出缺少的項目。 |

## 執行中的詢問怎麼回答

### 「帳戶『X』是哪一種？」

舊帳戶沒有種類。名稱剛好是 `現金`、`銀行`、`信用卡`、`一卡通`、`電子支付` 時自動判斷，其他名稱會問。輸入 `cash`、`bank`、`credit_card`、`e_wallet`（或中文：現金、銀行、信用卡、電子支付）後按 Enter。

### 「帳戶『X』在 2026-10 月底……的餘額是多少？」

App 的帳戶餘額＝開帳餘額＋開帳日以後的收支、轉帳與帳內投資買賣淨額。開帳日是搬遷截止月的下個月 1 號（預期為 **2026-11-01**），所以這裡要的是 **2026-10 月底那一刻**該帳戶的餘額。

- **現金、銀行**：工具會自動用財務文件裡「最近一筆核對紀錄」回推（核對時填的現金／銀行，加上舊系統核對時算出的「倒回月底後交易」調整），並在摘要列出用的是哪一筆核對。條件很嚴：最近一筆核對必須正好是搬遷截止月（2026-10）的核對，且當時有倒回月底後的交易（或餘額日期就是月底）。不符就改為詢問。
- **信用卡、一卡通與其他帳戶**：一律詢問。舊系統核對時不會倒回這些帳戶月底後的交易，信用卡的正負號也沒有留下可確認的依據，所以不猜。信用卡請填 **未繳金額的負數**（例如未繳 5,027 元就輸入 `-5027`）。沒有餘額就輸入 `0`。
- 回答格式是整數（新台幣元），可含逗號。格式不對會再問，連續三次不對就停止。

### 投資交易沒有帳戶時

舊投資表未保存帳戶。開帳日前的投資交易保留沒有帳戶，不影響新帳戶餘額；開帳日以後的帳內買賣則必須逐筆用 `--investment-account` 指定。缺少對應時工具會列出來源交易編號與日期後停止，補好參數再重跑，不修改來源匯出、不猜帳戶。未知編號、未知帳戶、歷史列或非帳內買賣的對應都會拒絕。

累計投入淨額仍採舊系統的期初次月起帳內買減賣規則，與帳戶開帳日分開。

## 停下來的情況（沒有產生輸出）

工具遇到需要你決定的事不會自己改資料，會印出清單並以結束代碼 2 停止：

| 訊息 | 意思與做法 |
|---|---|
| 分類「X」同時用在收入與支出：收入 a 筆、支出 b 筆 | 舊帳同一個分類名稱兩邊都用過。要繼續就必須決定：加 `--mixed-flow split`，把**收入**那一邊拆成「X（收入）」另一個分類，支出維持原名（不論哪邊筆數多；因為預算歸屬是以支出分類名稱為準）；金額與收支別不會被改。不想拆就先回舊帳處理，再重新匯出。 |
| 金額不是大於 0 的整數／日期缺漏或格式不認得／分類為空／帳戶為空／收支別不是「收」或「支」：n 筆（舊系統編號 …） | App 不接受這些列。工具**不丟棄、不修改**，請依編號到舊帳確認後重新匯出，或把清單回報給我們決定。 |
| 名稱只差大小寫或前後空白 | 例如 `Food` 與 `food `。不自行合併，請回報。 |
| 財務文件經帳本服務讀回後與來源不同 | 為免悄悄改動舊帳而停止，請回報。 |
| 帳本服務拒絕了這批舊帳（含「非 nullable 的字串欄位是 null」） | 舊系統理論上不會輸出這種值；請把完整訊息回報，不要手改匯出檔。 |
| 還缺少下列資料，而且沒有辦法詢問 | 用了 `--no-prompt`，或沒有互動終端。照訊息補上 `--account`／`--opening`。 |

## 結束代碼與其他失敗訊息

| 代碼 | 意思 |
|---|---|
| 0 | 成功，已印出摘要。 |
| 2 | 需要你處理（上表）、輸入與 baseline.md 記錄的基準不符，或輸出位置不合規定（不在 `.private/` 之下、檔案已存在、遺留 `.partial`、資料夾不存在）。 |
| 1 | 其他失敗。若訊息含 `Checksum differs`、`Unsupported or unverified baseline manifest`、`inventory differs`、`Incomplete export`，代表**來源匯出沒有通過驗證**：不要修改它，重新取得已驗證的匯出。 |
| 64 | 參數用法錯誤，會印出用法。 |

## 比對（轉換成功之後做，票 05）

目的：確認轉換出來的帳本檔，跟舊系統**逐月、逐項數字相同**。比對工具只讀、不改任何東西：不改舊系統、不改匯出、不改帳本檔（它只讀帳本檔在 `.private/` 底下的一份暫時副本，跑完刪掉，並用 SHA-256 確認原檔前後位元組相同）。

### 執行

用**轉換時同一份**匯出資料夾，和轉換出來的帳本檔。在 repo 的 `apps/mobile` 之下：

```bash
cd apps/mobile
npm run legacy-compare -- \
  ../../.private/<匯出資料夾> \
  ../../.private/app-ledger/ledger.sqlite \
  ../../.private/app-ledger/compare-20261112.md \
  --manifest-sha256 <轉換摘要印出的「來源清冊 SHA-256」>
```

- 第三個參數是**完整報告**的檔名：必須在 `.private/` 之下、事先不存在（已存在就拒絕，不覆寫；要重跑請換檔名）。**摘要**會自動寫在旁邊，檔名是 `<報告檔名>-summary<副檔名>`，例如 `compare-20261112-summary.md`。
- 匯出會用與轉換時相同的方式驗證（逐檔 SHA-256、與 baseline.md 記錄的基準身分相符）；不符就拒絕。
- **建議一律加 `--manifest-sha256`，值用轉換摘要印出的「來源清冊 SHA-256」。** 工具沒辦法自己確認「這個帳本檔是由這份匯出轉出的」（帳本檔裡沒有記來源）；配錯只會顯示成一堆差異（結束代碼 3），不加這個選項就釘不住「轉換時那一份」。月份清單與來源不同時，摘要與報告會多一行「帳本檔可能不是由這份匯出轉出」。
- 報告與摘要的路徑不能在匯出目錄裡面、不能就是帳本檔、兩者也不能是同一個檔；第二個參數必須是轉換程式輸出的帳本檔（空檔、不是 SQLite、或沒有帳本資料表的檔案會被清楚拒絕）。
- **比對中途不要按 Ctrl-C，也不要同時跑兩個比對。** 暫時副本（內含完整帳本）在 `.private/legacy-compare-tmp-*/`。比對只要幾秒；中途按 Ctrl-C 通常會等這次比對跑完才生效，副本一定會刪。被強制殺掉（或斷電）才會留下副本，下次執行一開始會偵測並刪除，並印出一行說明（所以同時跑兩個會互相刪掉對方的副本而失敗，原帳本檔不受影響）。
- 帳本檔旁邊如果有 `-journal`、`-wal`、`.partial` 殘留檔，工具會拒絕，請重新轉換一份新的。

### 它比對什麼

**門檻項目（任何一項差異不為 0 就失敗；容許誤差 0 元）**

1. 逐月（來源有的每個月，預期 2022-01 到 2026-10 共 58 個月）：從 App 的帳本服務查出當月收入、當月盈餘、可用餘額、學費儲備、總儲備金、各分類儲備、上限快照、帳面總資產，與來源比對。每個欄位最多兩道：
   - **舊系統的獨立資料表**：`dbo.Property`（收入、可用餘額、學費儲備、總儲備金、帳面總資產，58 個月）、`dbo.budget`（逐月列的當月盈餘，只有 55 列；1911-01-01 那一列是目前累計儲備，用來比對最近月份的各分類儲備）、`dbo.BudgetCap`（上限，只有 28 列）。
   - **來源財務文件的原始值**：所有月份都比。舊表沒有資料的月份（例如沒有 `dbo.budget` 列的月份）只能做這一道；報告會逐一列出是哪些月份，**不會補造缺的月份**。
2. **17 個月的歷史總資產差異同額重現**：每個月 App 查出的差異金額，要等於 `dbo.Property` 推得的（總資產－可用餘額－學費儲備－總儲備金）和財務文件記的；帳面總資產（含差異）要等於 `dbo.Property` 的總資產。月份數由來源算出，工具預期是 **17**（2026-11-08 基準）；算出來不是 17 就是門檻差異（只有程式介面能改預期值，命令列沒有旗標）。**這和轉換基準身分的「歷史資產差異 0」是兩回事**：後者是舊資料表（`dbo.Property`）與財務文件逐月不符的月數（要是 0，否則來源匯出不合格）；前者是財務文件裡記有非 0 歷史總資產差異（`LegacyTotalDifference`）的月份數（17，要原樣保留、同額重現，不是要消除）。
3. **整份財務文件**：帳本服務讀回的財務文件（含根層的上限版本與開放月份的上限、調整、核對紀錄、各月儲備變動）要與來源文件逐項相同。
4. **交易**：筆數與金額加總（總計、收入、支出、分月、分類、帳戶、逐筆內容），來源匯出 vs App。轉換時若用了 `--mixed-flow split`，「原名（收入）」只在「來源把原名當支出分類用、App 這邊是收入」時併回原名再比；併回的名稱全部列在完整報告。

**不算失敗、但會在結論旁（摘要放計數、完整報告列月份）告訴你的事**：獨立舊表沒有資料、只能與來源文件比對的月份數（當月盈餘、上限快照、資產欄位）；`dbo.BudgetCap` 的列已過時（該月不是舊帳原樣帶入的月份，例如撤銷後重結；舊網站不回寫這張表，所以不拿來比）；`dbo.budget`／`dbo.BudgetCap` 裡不屬於已結月份的列。

**累計列的「其他」差額**：`dbo.budget` 1911-01-01 那列和最近月份的各分類儲備是門檻項目。若「其他」的差額恰好等於「Property.budget（最近月份）減累計列十類合計」，完整報告會註明「差額等於舊資料的期初基準差額，屬舊資料未同步，不是轉換或 App 的錯」，但它仍然算差異，由我們判斷。

5. **信用卡明細**：日期、店家、金額與數量的多重集合，以及總筆數、金額加總；舊表沒有卡識別，不猜測逐列卡歸屬。
6. **投資**：全部標的（含停用）的成本、最新市值、已實現損益與配息，期初宣告與結算月月底的累計投入淨額，以及全部交易、市值歷史。來源算法獨立模擬 C# decimal 的中間精度與捨入，不使用 App 的投資計算器當期望值。原貌比對不含來源未保存的帳戶；轉換階段另讀回驗證明確指定的帳戶。

通過時的結論是「已比對範圍（逐月數字、交易、信用卡明細、投資）全部通過，0 差異」。仍需完成舊測試案例移植、新舊並行兩個月與本人簽核，才算整個搬遷驗收完成。

**重算報告（只列差異，不影響成功或失敗）**：用 App 的月結引擎，以現在的交易把各月重算一遍，列出與存檔數字的差異。舊系統本身就明定舊月份不能用現在的交易重算（早期有手動調整、只有部分月份留有上限紀錄），所以**差異不代表 App 算錯**；做不到的月份會標「無法重算」並寫原因。方法與限制寫在完整報告的第三節。

### 結束代碼、留下哪些檔案、殘留檔怎麼處理

- 看結束代碼：跑完馬上輸入 `echo $?`（要在下一個指令之前）。0＝通過、3＝有差異、2＝輸入或位置問題、1＝其他、64＝用法錯誤。
- **成功（0）或有差異（3）之後**：`.private/` 裡多兩個檔：完整報告與旁邊的 `-summary` 摘要（權限 600），沒有別的；暫時副本已刪。帳本檔與匯出沒有動。
- **失敗（1、2、64）之後**：沒有報告與摘要，暫時副本已刪。另有一種少見情況：比對出差異但報告寫不進去，結束代碼仍是 3，這時沒有留下檔案，摘要只印在終端機。報告與摘要是先寫成 `.partial` 暫存檔、兩個都寫成功才改成正式檔名；寫失敗時會收回，訊息會說明「沒有留下任何報告或摘要檔」或列出還存在的檔案。
- **殘留檔怎麼辦**：`.private/legacy-compare-tmp-*`（被強制中斷留下的暫時副本）不用管，下次執行會自動偵測並刪除；也可以自己刪。報告與摘要檔名後面加 `.partial` 的檔（例如 `report.md.partial`、`report-summary.md.partial`，訊息會列出）請確認不需要後自己刪除，否則重跑會被擋；刪除前不要打開來貼到任何地方。帳本檔旁的 `-journal`／`-wal`／`.partial` 代表帳本檔本身有問題，請重新轉換。

### 報告在哪、怎麼看

- 完整報告：你給的第三個參數那個檔案（Markdown，用文字編輯器或 Markdown 檢視器開）。結構：結論（含尚未涵蓋、沒有獨立來源與孤兒列的資訊）→ 一、逐月門檻比對（每個欄位用的來源、沒有獨立舊表來源的月份、歷史差異表、差異清單）→ 二、交易比對 → 三、重算報告（方法、限制、逐月結果、有差異月份的明細）。
