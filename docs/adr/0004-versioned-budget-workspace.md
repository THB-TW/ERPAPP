# 動態預算以類別識別碼與版本化財務文件保存

已同意新增／停用支出類別、逐次上限版本、月結快照與獨立調整，因此 ADR 0002 選擇固定欄位的前提不再成立。新模型用穩定的類別識別碼表示上限、歸屬、儲備及實支；原始月結、調整與核對各自留存，既有固定欄位只負責移轉與舊報表相容投影。

這是個人單一帳本，採 SQL Server 內一份版本化 JSON 財務文件作為一致性邊界；SQL 約束 JSON 格式及文件版本，所有財務寫入與交易異動共用交易範圍的應用鎖。文件更新、Property 投影及舊報表投影在同一筆 SQL 交易提交，表單附版本與操作識別碼以防止過期覆寫及重送。選擇整份文件犧牲大型多帳本的局部查詢效率，換取此資料量下原始快照、調整與版本的原子一致性；純計算仍獨立於 SQL 與 MVC。

舊資料只帶入已存結果，保留既有累計儲備基準及四項資產數字，不拿現在交易重算舊月份。少數舊月份的總資產與組成加總不符，另存歷史差異並原樣顯示；涉及這些差異或缺漏上限的撤銷／更正先停止，待查核處理。歷史逐類餘額的移轉基準與差額亦明確標記，不當作當年留存的完整快照。

`Property.Date` 改為 EF 的追蹤鍵，直接 SQL 腳本增加日期唯一索引，確保投影真的寫入；仍不使用舊 EF migration。核對紀錄保存當時輸入、餘額日期、倒回明細、帳面與結果，後續交易或更正不覆寫原核對。

此決定取代 ADR 0002 的固定欄位儲存方式；「開放月份可改、已結快照凍結」原則沿用。原型與訪談規格見 `.scratch/budget-adjustments/`。
