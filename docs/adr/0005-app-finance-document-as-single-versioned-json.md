# iPhone App 的財務文件沿用單一帶版本的 JSON 文件

2026-11-11 決定（規格「資料模型」）：App 的預算狀態——預算類別、上限版本、月結、月結歷史、調整、操作收據、核對紀錄——沿用 ADR 0004 的做法，整份存成一份帶版本號的 JSON 財務文件，放在手機上的 SQLite 內。交易、轉帳、帳戶、分類等流水資料另用一般資料表保存，不放進這份文件。

理由：月結與調整引擎本來就是「狀態＋指令 → 新狀態」的純函式，原樣移植到 TypeScript 風險最低，也最方便和 58 個月舊帳逐月比對；個人單一帳本的資料量不需要把預算狀態拆成多張表。代價是這份文件的局部查詢效率不如拆表，但資料量小，換到的是原始快照、調整與版本在同一個資料庫交易內原子一致，並且沿用舊系統已驗證的並行控制（文件版本號與操作識別碼防止過期覆寫與重送）。

這張票（App 骨架）只建立資料庫與交易、帳戶、分類三張表；財務文件與引擎在票 03 才移植，屆時以新的結構遷移加入。資料庫以 `PRAGMA user_version` 記錄結構版本，備份檔帶同一個版本號。
