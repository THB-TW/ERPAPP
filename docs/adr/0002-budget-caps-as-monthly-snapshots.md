# 預算上限存成每月快照，由月結凍結

2026-11-07：固定欄位的儲存決定由 ADR 0004 取代；開放月份與已結快照凍結的原則沿用。以下保留原始背景與取捨。

預算上限原本寫死在 `sp_FinanceSummary`，要調整只能改 SP，而且改了之後撤銷舊月份會用新上限重算、把總儲備金扣錯。
現在上限存在 `dbo.BudgetCap`（一個月份一列），SP 讀「該月或最近一個較早月份」的列；月結時若該月沒有自己的列，
SP 把沿用值寫成該月的快照。網站只准改**開放月份**（最近一次月結月份的次月），已結月份的快照不能改。

## Considered Options

- **單一一組現行上限（只有一列）**：改上限最簡單，但撤銷舊月份時會用到改過的上限，回滾不再剛好抵銷。否決。
- **每月一列、每次月結前都要先手動建好**：使用者忘了建就無法月結。改為「沿用＋月結時凍結」，平常不調就什麼都不用做。
- **長表（月份, 分類, 上限）**：分類可以增減，但 `budget` 表本身是固定欄位，增加分類一定要改表與 SP；
  寬表與 `budget` 欄位一一對應，SP 一次 SELECT 取完。選寬表。
- **「當月」用日曆月份**：月結通常在次月初做，日曆上的本月往往還不是要結的那個月。用開放月份。

## Consequences

- SP 裡不再有任何金額常數；總開銷由上限算出（-(12 個上限＋學費儲備)），學費儲備提撥也改讀快照。
- 2024-08～2026-09 用現值回填（由 budget 結餘＋實支反推，期間上限不變）；更早的月份沒有快照，也不能再撤銷，所以用不到。
  電話網路、gogoro電費的歷史上限無法反推（兩者在總開銷裡正負抵銷），回填現值，不影響任何已存數字。
- 撤銷後快照保留：被撤銷的月份重新成為開放月份，可以改了再結。
- 找不到任何快照時 SP 直接報錯、不寫入，避免用 0 當上限默默算出錯的儲備。
