# 帳本服務是唯一的測試切入點，資料庫驅動是唯一的轉接點

2026-11-11 決定（規格「平台與架構」「Testing Decisions」）：App 分三層，依賴只往下——畫面、帳本服務、純計算。畫面只負責顯示與收集輸入，不含帳務規則，也不直接碰資料庫；帳本服務對上提供「指令」（例如新增交易）與「查詢」（例如月曆、當日交易），所有寫入在同一個資料庫交易內完成，無效輸入以繁體中文訊息拒絕；純計算（日期、之後的預算引擎與 CSV 解析）是不碰資料庫的純函式。

帳本服務只認一個很小的非同步資料庫介面（執行、查詢、交易），有兩個實作：手機接 expo-sqlite，測試與 Mac 工具接 Node 內建的 `node:sqlite`。兩者都是真的 SQLite，檔案格式相同，所以測試不模擬資料庫，每個測試開全新的記憶體資料庫。

測試只經由帳本服務下指令、查結果，不檢查資料表或 JSON 的長相，之後重構儲存方式測試不必改；純計算只在從帳本服務難以構造輸入時才另寫直接測試。畫面不寫自動測試，由翰陞在 iPhone 上照票的驗收步驟實際操作。選這個切入點是因為它在雲端容器就能用 Node 跑完，不需要 iPhone 或 Mac，而且涵蓋規則所在的那一層。

代價是 expo-sqlite 驅動本身不被雲端測試覆蓋（只過型別檢查與打包），要靠真機驗證；因此驅動刻意保持薄，不放任何規則。
