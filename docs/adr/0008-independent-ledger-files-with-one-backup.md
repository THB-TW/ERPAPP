# 多帳本各自一個資料庫檔，備份打包成一個檔

2026-11-25 翰陞決定（`.scratch/ledgers-trend-icons/spec.md` 第 11–17 點）：App 可建多個帳本，每本完全獨立，各自一個 SQLite 檔；App 層另有一份帳本清單（名稱、排序、檔名）與全域設定（上次備份日期、記帳與備份提醒）。備份只有一個檔，內含全部帳本，匯入時整包取代。

考慮過的另一做法是在同一個資料庫的每張表加 `ledger_id`。那會讓所有帳本服務的查詢、月結計算、58 個月搬遷比對與 CSV 去重都多一個條件，任何一處漏寫就會讓兩本帳的數字混在一起；而翰陞要的是「完全獨立、不合計」。各自一個檔則讓帳本服務維持一本帳的模型（ADR 0006 的測試入口不變），舊的 58 個月帳本檔直接成為第一本，數字不必重驗。

代價：切換帳本要關閉再開啟資料庫、重排該帳本的通知；備份格式從「一個 SQLite 檔」變成「一包多個檔」，所以舊的單帳本備份仍須能匯入（匯入後只剩那一本）。跨帳本合計日後若要做，只能在 App 層逐本讀取再加總。
