# 動態預算與月結調整

規則定案在 `.scratch/budget-adjustments/design-interview.md`，儲存取捨在 ADR 0003、0004。

## 本機啟用

1. 備份既有 ERPDB，先還原到獨立驗證副本。
2. 對副本執行 `docs/sql/budget-workspace.sql`。這只增加財務文件表與 Property 日期唯一索引，不重算資產。
3. 以測試入口驗證舊帳四項金額，通過後才在正式資料庫執行同一腳本。先停止舊網站，避免舊 SP／上限頁繼續寫入。
4. 使用既有 `appsettings.json` 的連線啟動新網站。第一次讀取財務頁面時，原樣保存既有月結與上限基準；原本未留的核對、原因及完整歷史實支不補造。
5. 重啟網站並重新整理頁面。新增／停用分類與歸屬、上限儲存在預算上限；挪用在預算表；前期更正在月結精靈，所有調整先預覽。

既有的 repo 外 `SQLServer_SP.TXT`、`import_data.py` 與手動匯入批次只作舊流程參考，新的月結與匯入應經網站執行。新文件與既有投影若不同，服務會停止財務更新，先查核外部修改的來源，不直接覆蓋。

## 測試

本專案提供不需額外測試套件的可執行測試入口；這不是 `dotnet test` 的測試探索專案。

```powershell
dotnet build ERPAPP.sln
dotnet run --project tests/ERPAPP.Tests.csproj
dotnet run --project tests/ERPAPP.Tests.csproj -- --integration
```

`--integration` 固定連到 `.\SQLEXPRESS` 的 **ERPDB_BudgetVerify_20261107**，不接受正式 ERPDB 作測試目標。先將本次升級前的備份還原到這個獨立名稱並執行 SQL 腳本；整合案例中的更正、撤銷、重結與匯入在測試交易中回滾。首次讀取留下移轉基準，以便重跑。初次驗證的副本包含 58 個月份。

測試涵蓋：前期更正傳遞、待重結、原始快照、版本保存、分類歸屬、挪用守恆、沖銷、過期版本、重送、未知分類、無效金額與已結交易拒收；SQL 案例也核對實際 Property 投影，而非只檢查記憶體結果。

## 舊資料與啟用基準

2026-11-07 備份中的 10 月收入已為 **50,358**、可用餘額 **61,406**、帳面總資產 **285,967**；系統移轉不再扣 700 元，也不自動建立任何更正。原型中的 -700 只是驗收情境。

58 個舊月份的 Sparemoney、Tuitionfee、Budget、Totalproperty 均保留。發現 17 個月份有原有總資產加總差異，歷史頁明列，涉及的撤銷／更正先停止查核。新月結的 Totalproperty 由組成重新計算；舊異常不在這次升級中自動修補。

原因、版本與調整都追加保留。核對的餘額日期限制為結算月底至今天，倒回只計到該日；原核對結果不隨後續交易改寫。
