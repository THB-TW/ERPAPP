# 手機快速記帳：實作與驗收方向

2026-11-08 使用者補充：資料庫、語言、架構與套件均可重新審核，資料與現有功能要保留；手機記帳必須方便、快速。

## 實作方向

- 主畫面捷徑進入即為記帳入口，金額與常用分類在首屏；不先經過圖表或財務總覽。
- 金額數字鍵盤、常用分類一點選擇，沿用上次帳戶與常用成員，日期預設台北今天；全部可快速修改。
- 可單手操作，主要按鈕至少 44px；不放大型 UI 套件或非必要裝飾資源。
- 儲存後仍停在記帳入口，清楚顯示本次結果與該分類剩餘預算，可立即記下一筆。
- 顯示真實狀態：已存雲端、僅暫存手機、傳送中、需要重試。只有伺服器確認成功才顯示已存帳。
- 弱網路下保留輸入與待送佇列；同一筆有固定操作 ID，重試或連點不重複入帳。離線資料按登入使用者隔離，不混入另一帳號。
- 預算、歷史、月結及投資採分頁/延後載入，不阻塞記帳首屏；圖表只在使用者打開相關頁面時載入。
- 本月預算不等上月月結或發薪才更新；正式月結及歷史儲備另行標示，未確認結果不能冒充正式資產。

## 架構與套件取捨

- 先以 TypeScript、輕量 HTML/CSS 手機介面、Worker API 與 D1 為實作基線；不綁舊 MVC/SQL Server，也不因偏好新框架而增加首屏負擔。
- 舊 C# 計算與驗收案例保留為移植比對依據；「保留功能」以行為、數值、歷史紀錄一致為準。
- 一般記帳的新台幣整數做安全整數/範圍驗證；投資數量與價格維持十進位精度，不直接轉 float。
- 套件只在確有需求時引入。解析 CSV、驗證登入及精準十進位等容易出錯的部分，評估成熟套件；圖表和其他重套件延後載入。
- 登入限制本人；API 不以隱藏網址作保護；私人備份和舊密碼永不進入前端套件或部署資源。
- 不啟用自動付費升級。Cloudflare、LINE 與備份配額需可觀察；月費上限 NT$200，免費限制不符時先調整設計與揭露選擇。

## 待實測的速度驗收

以下是目標，並非已達成的測量：

| 情境 | 目標 |
|---|---|
| 常用路徑 | 開啟 → 輸入金額 → 點分類 → 儲存；預設日期/帳戶/成員不需重選 |
| 重複開啟主畫面 | 快取介面可在 1 秒內進入可輸入狀態 |
| 第一次開啟 | 在實際 iPhone 一般 4G 網路下，以 2 秒內可輸入為目標 |
| 首屏資源 | 記帳主要 HTML/CSS/JS 合計以 gzip 50KB 內為目標，不含延後載入功能 |
| 儲存互動 | 按下後 100ms 內顯示處理狀態；正常網路下 1 秒內確認或揭露延遲 |
| 斷線/重送 | 不遺失輸入、不假裝成功、不重複入帳；重新連線可恢復 |
| 免費方案 | 在真實 Worker/D1 環境測量 CPU、查詢與容量；本機 SQLite 通過不取代雲端效能驗證 |

先在新版本驗證這條快速記帳路徑，再把月結、歷史與投資完整接上；全功能與資料核對完成前不切換正式入口。
