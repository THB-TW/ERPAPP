## 正式行為

- 共用導覽標示目前頁面，手機可展開；頁首說明當頁用途。
- 預算表依序呈現可用餘額、正式補入／挪用表單及類別明細。明細的「補足」可帶入類別與缺口，仍須填原因並經伺服器預覽後確認。
- 上限設定分成安排上限、整理類別與查看快照；月結保留四步驟，預覽分成原因、金額與確認保存。
- 登入、交易 CRUD、信用卡、分析、投資、歷史與錯誤頁沿用同一組表單、色彩、標題及提示；交易操作使用中文名稱。
- 表格保留欄位、歷史版本與明細，數字使用等寬數字，窄畫面在表格內橫向捲動。新增的捲動區域可由鍵盤聚焦；後續 AJAX 輸出的核對表也使用相同處理。
- 共用 CSS 在 `wwwroot/css/site.css`，共用導覽在 `Views/Shared/_Layout.cshtml`，表格與預算快速帶入在 `wwwroot/js/app-ui.js`。Bootstrap 沿用專案的 5.1，未新增套件。

沿用原有表單端點、操作識別碼、版本、防偽欄位與編輯權限。原型候選資產與舊預設 Layout scoped CSS 不在正式版保留；舊碼由 Git 回查。此次不修改正式資料庫或金融計算。

## 驗證與啟動

Razor 與方案建置成功；目前保留 6 項原有登入／員工模型 nullable 警告。純計算與 SQL 副本整合測試通過。

另以獨立工具在記憶體中渲染 19 份實際 Razor 頁面為離線 HTML，以驗證副本的歷史資料及投資空狀態檢查 1440px／390px 寬度。檢查桌面與窄畫面無整頁橫向溢出、資金來源頁籤、類別快速帶入、手機導覽、唯讀顯示、預覽表單端點與防偽欄位、月結前後步驟。支出分析及月結的 API 回應由驗證工具模擬，沒有從離線頁面執行金融寫入；圖表使用原有 Chart.js。

這些檢查未啟動 HTTP server；實際登入、Cookie 往返與正式確認提交仍需在使用者啟動網站後操作。

```powershell
cd "C:\Users\User\Documents\記帳\SQLEXPRESS\ERPAPP"
dotnet run --launch-profile http
```

看到 `Now listening on: http://localhost:5015` 後開啟網址；保留終端機查看紀錄，Ctrl+C 停止。測試資金調整時，預覽頁尚未寫入，按確認才會更新帳目。
