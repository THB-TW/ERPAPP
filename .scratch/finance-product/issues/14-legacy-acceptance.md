# 決定 58 個月舊帳月結的驗收方法

Type: grilling
Labels: wayfinder:grilling
Status: resolved
Blocked by: 18-local-first-stack

## Question

新引擎怎麼證明和舊系統一致？比對哪些數字（每月當月盈餘、可用餘額、總儲備金、學費儲備、帳面總資產、各分類儲備、上限快照、前期更正）、容許誤差（應為 0）、比對資料從哪來（`docs/cloudflare/baseline.md` 的私人匯出，由翰陞提供，不進 Git）？是把 `BudgetEngine.cs` 移植成 TS 後跑同一批案例，還是新舊並行一段時間？驗收通過的簽核方式。

## Answer

2026-11-10 翰陞五題都照建議：

1. **比對項目**：2022-01 至 2026-10 每月逐月比對當月收入、當月盈餘、可用餘額、學費儲備（之後為貸款／分期）、總儲備金、各分類儲備、上限快照、帳面總資產，**容許誤差 0 元**。另整體核對 7,033 筆交易與 605 筆信用卡明細的筆數與金額加總，以及投資的成本、市值、累計投入淨額。
2. **兩層方法**：(a) 舊帳原樣匯入 App 當歷史紀錄、不重算，逐筆確認與來源相同；(b) 移植成手機版的月結規則，從原始交易、上限快照與調整一路重算 58 個月，每月結果須等於舊系統存的月結。
3. **17 個月原有總資產加總差異**：原樣保留不修補；重算時列為「已知歷史差異」，差額須與舊紀錄完全相同才算通過，其餘月份一律 0 差。
4. **資料來源**：用 2026-11-08 已驗證的唯讀備份匯出（`ERPDB_CloudflareBaseline_20261108_115129`，SHA-256 見 `docs/cloudflare/baseline.md`），由翰陞從 Windows 私人資料夾複製到 Mac；比對程式在翰陞的 Mac 上執行，私人帳務不進 Git，Git 只放結果摘要。
5. **並行與簽核**：重算通過後並行 2 個月（例如 2026-11、12），舊系統照常記帳、每月匯入 App，兩邊各自月結須一致；通過後由翰陞簽核即完成驗收。舊系統退役另案決定。
