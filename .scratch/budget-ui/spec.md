# 預算介面探索

Decision: pending user selection

問題：哪種資訊層級能讓使用者最快找出缺口，並明確理解從可用餘額或其他儲備補入的影響？提供三個結構不同的預算表版本，沿用既有登入、資料讀取及外層導覽。

- A 留白總覽：餘額摘要、缺口卡片、右側補入表單。
- B 帳本工作台：深色資產側欄、密集分類帳、調整面板。
- C 補足引導：來源確認、資金安排、類別餘額三個步驟。

入口 `/Finance/BudgetReport?variant=A`（或 B／C），僅 Development 啟用。底部切換列與方向鍵切換、更新網址，輸入框內不攔截方向鍵。初始讀取真實帳目，所有原型操作只在記憶體模擬；重新整理／重設後還原。原型不呼叫任何調整寫入端點；不帶 variant 的正式預算表仍可操作真正的補入功能。

原型保存在 `prototype/budget-ui-20261107` 分支；使用者選定後才將選中的設計重新實作至正式頁面，清除候選版與切換器。完整原型來源保留於該分支。此輪尚未選定，沒有把三套候選介面併入 master。

目前集中預算表的資金補足流程。全站導覽、月結、上限、交易等畫面可依選定視覺方向再統一，不把這三套候選原型當作全站改版完成。

驗證：Razor 建置通過；以離線合成資料檢視三版及 390px 窄螢幕，模擬補入、網址切換與輸入鍵盤操作正常，無頁面溢出或 JavaScript 錯誤。未啟動 HTTP server；實際登入後的版面由使用者自行啟動網站查看。
