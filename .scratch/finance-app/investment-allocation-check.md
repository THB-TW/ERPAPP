## 結論與處理分類

**屬於任務 (b)：只寫報告，不改程式、測試或帳務資料。**

現行 TypeScript 的分配公式沿用舊 C# 的設計意圖：

```text
非投資部分＝帳面總資產 B－累計投入淨額 D
財產分配合計＝B－D＋投資市值 V
```

**就程式與規格而言，這是設計如此，沒有找到本案例的畫面重複加總錯誤。** 但也不能把設計簡化成「帳面總資產一律完全不含投資」。帳面沒有直接加進部位市值，卻可能仍保留從帳內轉去投資的金額；D 正是要扣掉的帳面高估額。帳外投資及已在歷次月結／更正中消化的歷史投入，不必仍包含在帳面裡。

因此，合計可以大於、等於或小於帳面總資產。以畫面所示 D＝0 為前提，**423,815 元是正確公式結果**；是否符合真實財產，仍取決於期初宣告及後續帳內買賣是否正確。只憑提供的畫面，無法證明 D 應大於 0，也無法確認 D＝0 的業務事實。若宣告漏填，畫面可能高估，但那是與月結核對共用的資料／定義問題，不能用畫面補扣市值或成本來掩蓋。

目前文字確有理解落差：卡片先列「帳面總資產」，最後只寫「合計」，未明示兩者口徑與時間基準不同，容易讓人以為分配合計必須等於帳面總資產。這是可以另案改善的標示，不足以授權改變金額公式。

### 舊圖與 TS 的歷史差額細節

舊 C# 圖的非投資總和是 `(Sparemoney－D)＋Tuitionfee＋Budget`，TS 使用 `bookTotal－D`。如果該月 `Totalproperty` 不等於這三個用途金額之和（有保留的 `LegacyTotalDifference`），兩個圖的非投資值可能相差該歷史差額。

這個差別可由上表的 C# Controller、`BudgetState.cs:56-60` 及 TS 預算引擎證實；**本次沒有讀真帳，不能斷定畫面所用月份存在這種差額**。它屬於歷史帳面定義，不能擅自修改或把歷史差額歸零，也不能當成本題已發生的重複計算原因。

## 投入淨額為 0 是否合理

可以合理，但需要分清楚下列情況：

1. 期初仍高估帳面的投入確實為 0；持有部位來自帳外資金，或歷史投入已在月結／更正中消化。即使有非零成本與市值，D 仍可為 0。
2. 期初為 0，期初之後帳內買進與帳內賣出價金淨額恰為 0，D 仍為 0。帳外交易、補期初部位或補快照本來就不會增加它。
3. 期初宣告遺漏、明確保存了錯誤的 0，或後續資金來源標錯，也可能讓 D 不實地變成 0；這是待確認的資料事實，無法從市值反推。

本題畫面顯示「2026-07 月底 0 元」，而不是「尚未設定（以 0 元起算）」。依 `apps/mobile/src/app/investment.tsx:158-161`，這表示查詢取得了非空的期初結果；它可能來自明確投資期初列，也可能來自開帳設定的讀取轉接，**不能直接判定為完全沒設定**。明確的 0 也會優先於開帳設定：`apps/mobile/src/ledger/onboarding.test.ts:232-244` 已有此合成測試。

要判斷這個 0 是否可信，須由翰陞確認截至宣告月底「還留在帳面、但已轉成投資」的金額，再核對其後帳內買賣的日期與資金來源。不能改填整體持有成本、137,848 元市值，或把 ADR 的歷史例子金額當作本帳應填值。

## 以題目數字推算

| 項目 | 金額（元） |
| --- | ---: |
| 帳面總資產 B | 285,967 |
| 累計投入淨額 D | 0 |
| 非投資部分 B－D | 285,967 |
| 虛擬貨幣市值 | 66,323 |
| 凱基台灣 TOP50 市值 | 13,880 |
| 台積電市值 | 57,645 |
| 投資市值合計 V | 137,848 |
| 財產分配合計 B－D＋V | **423,815** |

所以在現有宣告可信、其他輸入一致的前提下，正確分配合計為 **423,815 元**，比帳面大 137,848 元；這不是單憑相減即可認定的重複金額。

如果查明真正的「累計投入淨額」應為 D*，則正確非投資部分為 `285,967－D*`，分配合計應為 **`423,815－D*` 元**。只有 D* 恰好等於 137,848，合計才等於 285,967；沒有證據支持這個等式。提供的數字不足以算出 D* 或承諾真實財產一定為 423,815。

百分比分別是 67.4%、15.6%、3.2%、13.6%，與分母 423,815 一致。`apps/mobile/src/app/investment.tsx:309-311` 以整數除法截到一位小數，因此加總為 99.8%；這個顯示捨去與本題的 137,848 元差距無關。

另需保留時間限制：B 是最近一次月結的帳面，D 是查詢日投入額，V 是各標的截至查詢日最新手動快照（未填則成本），不是保證同日、即時的完整淨值。舊 C# 也採最新月結搭配最新市值；本次未改此既有設計。
