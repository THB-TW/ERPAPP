# 04 — 舊帳轉換程式

**What to build:** 翰陞在 Mac 上執行一個命令列工具，輸入 2026-11-08 的唯讀備份匯出，得到一個 App 的帳本檔，裡面有全部舊帳。工具只給翰陞用，不打包進 App。

**Blocked by:** 03 預算與月結計算規則移植

**Status:** ready-for-agent

**Owner:** `legacy-migration`（見 `docs/agents/team.md`）　**Spec:** [規格](../../finance-product/spec.md)

- [ ] 輸入的雜湊與 `docs/cloudflare/baseline.md` 記錄不符時拒絕執行
- [ ] 輸出只能寫到 Git 忽略的私人位置，且不覆寫既有輸出
- [ ] 搬入：交易、財務文件（58 個月月結、上限版本、調整、核對紀錄）、帳戶、分類、成員；不搬員工帳號、密碼、權限與外部原始檔（信用卡明細在票 12、投資在票 20 補上）
- [ ] 58 個月以搬遷月份的身分原樣帶入、不重算；17 個月的歷史總資產差異保留並標記
- [ ] 各帳戶的開帳餘額取自最近一筆核對紀錄回推到搬遷截止月月底；沒有可用紀錄時在執行時詢問
- [ ] 自動測試只用虛構資料（依匯出格式產生的小型假資料）；repo 內沒有任何真實帳務
- [ ] 工具的使用說明寫成翰陞照做就能完成的步驟

## Comments

2026-11-11 待確認（票 01 審查時發現）：App 的分類帶有收支別，且帳本服務拒絕「收入分類記成支出」或反過來。舊帳與其他 App 的 CSV 可能有同一個分類同時用在收入與支出（例如退款記成該分類的收入）。做這張票時先用真實檔案的形狀確認；若有這種情況，要決定是放寬規則、拆成兩個分類，還是用負數支出表示，並回報翰陞決定，不自行改義。

2026-11-11 範圍調整與提醒（票 03 完成後）：
- 這張票只搬「交易、財務文件、帳戶、分類、成員」，足以做 58 個月比對。信用卡明細改在票 12、投資資料改在票 20 各自把轉換補上（那時 App 才有對應的資料表）；票 05 的對應總量比對也跟著補。
- 匯入財務文件用帳本服務的匯入入口。它會拒絕「非 nullable 的字串欄位是 null」的文件；舊系統理論上不會輸出這種值，實跑遇到要回報而不是悄悄改。
- 交易要有「成員」欄位才搬得進來，這張票要加這個欄位（遷移）。
