# 01 — App 骨架：記一筆支出並在月曆看到

**What to build:** 使用者打開 App 看到本月月曆並選在今天，按「新增」輸入金額、選分類與帳戶後按「儲存」，這筆支出出現在當天的列表，關掉重開仍在。這張票建立之後每張票都要用的三層（畫面、帳本服務、純計算）與資料庫驅動的兩個實作（手機與 Node），以及在雲端跑的測試方式。分類與帳戶先用程式內建的預設表（只有名稱，不含任何個人資料）。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

**Owner:** `ledger-entry`（見 `docs/agents/team.md`）　**Spec:** [規格](../../finance-product/spec.md)

- [ ] repo 內新的獨立目錄有一個可啟動的 Expo App（TypeScript），不改動既有 ASP.NET 專案與 C# 測試
- [ ] 帳本服務提供「新增交易」指令與「某月月曆」「某日交易」查詢；畫面不直接碰資料庫
- [ ] 資料庫驅動有手機與 Node 兩個實作，都是真的 SQLite；資料庫記錄結構版本並有遷移機制
- [ ] 資料庫檔放在會被 iCloud 裝置備份的位置
- [ ] 金額為新台幣整數、日期為台北時間的日期字串；分類不存在或金額不是正整數時指令拒絕
- [ ] 測試在雲端容器用 Node 執行，透過帳本服務驗證：新增後查得到、重開資料庫仍在、無效輸入被拒
- [ ] 補兩份 ADR：財務文件沿用單一 JSON 文件；帳本服務是唯一測試切入點
